# 聊天档案 Chat Archive

把聊天消息实时抄进自己的本地库，然后像查资料一样查自己的对话。

不消耗模型 token，只读不改聊天本身，数据全在 APP 私有库里，不上传任何地方。

---

## 它做什么

- **实时抄写**：每来一条聊天消息，后台就把原文抄一份进本地库。不调用模型，不花 token。
- **关键词搜索**：搜「卤肉面」「充电」「体育课」，连引用内容一起搜。
- **时间筛选**：按日期 + 小时定位，比如「11 月 3 日 14 点之后」。
- **上下文回溯**：点任意一条，能看到它前后各 8 条，还原当时在聊什么。
- **引用跳转**：引用消息显示成蓝色块，点一下跳到被引用的原消息。
- **多选操作**：长按进入多选，可以复制、转发给任意角色或群聊、删除。
- **已删除清理**：比对聊天里已经删掉的消息，勾选后从档案里清掉。
- **给角色用的工具**：注册了三个工具，角色可以自己搜档案、读上下文、看统计。

---

## 安装

1. 把 `chat-archive.zip` 导入 float 小手机。
2. 从聊天页的 **+ 号面板** 进入「聊天档案」。首次进入会自动把最近 200 条历史抄进来当底子。
3. 之后的新消息会自动累积。

> 从桌面直接打开拿不到当前会话 id，功能会受限，请从 + 号面板进。

---

## 已知限制

这些是平台本身的限制，不是 bug：

| 限制 | 说明 |
|---|---|
| 历史只能读最近 200 条 | 宿主的 `readHistory` 上限是 200，没有翻页参数。装上之前的旧消息补不回来，只能靠往后积累。 |
| 图片看不到 | 宿主没有把图像数据放进聊天历史。`mediaData` 里只有类型标记，没有图片本身。所以档案只能标「［图片］」，不知道画的是什么。 |
| 已删除比对只在时间窗内 | 只能比对最近 200 条历史覆盖的时间范围。更早的消息删了，档案发现不了。 |
| 工具记录 id 不稳 | `system` / `tool` 类消息的 id 每次读可能不同，所以不参与删除比对，避免误报。 |
| 引用跳转靠 id + 文字双保险 | 宿主给了 `quoteMessageId` 就直接定位；没给就退回文字匹配，匹配不上会弹候选列表让你自己挑。 |

## 数据结构

全部存在 APP 私有库 `AiPhone.db`，两张表：

**`archive_messages`** — 消息本体

| 字段 | 说明 |
|---|---|
| `msgId` | 宿主消息 id（用于去重和引用定位） |
| `sessionId` | 会话 id |
| `characterId` | 角色 id |
| `role` | `user` / `assistant` / `system` / `tool` |
| `content` | 正文（引用消息会剥掉 `[引用:xxx]` 外壳） |
| `quote` / `quotePreview` | 被引用内容的预览 |
| `quoteId` | 被引用消息的宿主 id |
| `quoteRole` | 被引用者角色 |
| `mediaType` | `image` / `sticker` / `media_file` / `app_card` / `quote` |
| `createdAt` | 消息创建时间 |
| `isRetracted` | 是否已撤回 |

**`archive_meta`** — 元信息（播种标记等）

---

## 隐私

- 所有数据只存在本 APP 私有库。
- 不联网，不上传，不调用任何外部接口。
- 卸载 APP 时宿主会一并清掉数据。
- 唯一的对外写入是「发给谁」功能：你主动选择转发时，会写一条历史消息到聊天里。

---

## 关于引用消息

float 的引用不是挂在消息上的字段，而是**一条独立消息**，`mediaType` 为 `quote`。它的 `mediaData` 里带：

```
quoteMessageId   被引用那条消息的真实 id
quotePreview     被引用内容的预览文本
quoteRole        被引用者角色
```

本 APP 靠这三个字段做跳转。如果你在别的项目里也要处理引用，这是关键。

| 每页显示多少条 | `const PAGE = 30` |

## 踩过的坑（给后来的人）

1. **不要把整页 HTML 塞进聊天消息**。宿主会把它当页面渲染，还会盖一层遮罩，整个聊天页会崩。要传结构化数据，用 `chat.writeHistory` 写一条纯文本，或者干脆不走聊天消息。

2. **`readHistory` 上限 200 条，没有翻页参数**。所以「抄写」比「查询」靠谱 —— 实时存下来才不会被 200 条卡住。

3. **`const` 有暂时性死区**。如果你把一大块数据常量放在脚本末尾，而开头就有代码引用它，整个脚本会静默挂掉，页面停在加载中。把常量放最上面。

4. **`system` 消息的换行会失效**。单个 `\n` 会被折叠成空格，要么用空行，要么改用 `assistant` 角色。

5. **工具 handler 必须一次拿到最终结果**。宿主自动循环只有 2~3 轮，返回「已交给后台」会让角色以为没结果，再调一次就撞上限了。

6. **`mediaData` 里没有图片本体**。只有类型标记（`image` / `sticker` / `media_file`），图片数据在插件层的 `msg.mediaUrl` 里，APP 侧拿不到。

7. **引用是独立消息，不是字段**。见上面「关于引用消息」一节。
